# 退職リリーフ｜PPC LP コピー・広告文デック v1

作成日: 2026-07-22  
対象: 検索広告から流入する、自己都合退職後の時期・手続きを確認したい人  
目的: LINE追加完了  
使い方: この文書をテキストワイヤーの正本とする。実装時に、広告主確認が必要な事実・素材だけを差し替える。

## 0. 固定する判断

### LPの役割

検索広告で得た疑問に、LP内でまず答える。そのうえで「自分の場合に当てはめて確認したい人」がLINEへ進む。

**LP内で出す答え**

- 確認する順番は、退職前・退職直後・書類待ちで変わる。
- まずは自分の現在地と、次に確認する項目を整理するとよい。

**LINEで確認してもらうこと**

- いまの状況に応じた確認事項。
- 退職リリーフの案内の進み方。

### 絶対に混ぜないもの

- 手続き時期を調べるAG1と、サポートを探すAG2を、同じ広告の約束で広く取らない。
- 公式LPの表現やサービス範囲を、確認なしに言い換えて拡張しない。
- 実在しない受給例・利用者の声・数字・LINE画面は載せない。

## 4. CTAの配置と計測

| 場所 | 表示文言 | 直前に解消する疑問 | イベント `placement` |
|---|---|---|---|
| FV | LINEで自分の状況を整理する | 自分向けか、何ができるか | `hero` |
| 時期別確認 | LINEでいまの段階を確認する | 自分はどの段階か | `stage` |
| 手続きノート | LINEで次に確認することを整理する | 何を順番に見ればよいか | `steps` |
| LINEの流れ | LINEで確認を始める | 追加後に何が起きるか | `flow` |
| 最終 | LINEで自分の状況を整理する | まだ残っている迷い | `final` |
| 追従 | いまの状況をLINEで確認 | ページを読みながらの再訪 | `sticky` |

各CTAには `cta_click` を送り、`placement`、`cta_label`、`intent_cluster` を同時に保存する。段階をタップした場合は `stage_select` に `pre` / `post` / `waiting` を保存する。

## 5. デザイン方向の選定

### 採用: A｜退職前後の手続きノート

- 静かなオフホワイト、濃いインク、深い青緑、CTAだけLINEグリーン。
- カレンダー・封筒・メモを使い、時期と確認順を一目で理解させる。
- モバイルは縦のタイムラインを主役にする。
- 競合に多い人物写真・ネイビー・金色・大きな数字と明確に距離を取れる。

### 保留: B｜相談デスクの編集ページ

- 白地、黒文字、朱色の注釈で「編集記事」のように見せる。
- 信頼感は出るが、手続きの流れを直感的に示す力はAより弱い。

### 不採用: C｜チャット中心のスマホUI

- LINE導線との親和性は高いが、実在しない会話画面を置くと作り物に見えやすい。
- LINEの承認済み画面素材が得られた場合だけ再検討する。

## 6. 制作に渡す固定仕様

```text
ページ形式: 状況整理・判断支援型の記事LP
主流入: AG1（自己都合・時期）
主CTA: LINEで自分の状況を整理する
視覚方向: A｜退職前後の手続きノート
必須要素: PR表記、更新日、時期別タイムライン、確認順、LINE後の流れ、FAQ、運営・ポリシー導線
禁止要素: 架空の実績・声・LINE画面、人物切り抜きの量産、カードの入れ子、意味のないアニメーション
初回のLPテスト対象: H1/サブコピー/CTA文言だけ。本文構造とKWは固定する。
```
